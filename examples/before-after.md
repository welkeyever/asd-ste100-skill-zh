# 改写示例：先保留含义，再简化表达

示例是人工编写的期望行为，不是模型效果评测结果。每个例子都说明哪些信息必须保留。句子缩短和 lint 提示减少不能替代语义核对。

## 工具描述：拆动作，保留条件

**原文**

> 本工具会尝试在已经配置的各个后端之间进行状态的同步，如果检测到冲突且策略允许自动解决，工具可能会自动解决冲突，如果策略不允许自动解决，工具会将冲突报告给管理员。

**改后**

> 本工具会尝试同步已配置后端之间的状态。检测到冲突时，工具按以下条件处理：
> - 策略允许自动解决时，工具可能会自动解决冲突。
> - 策略不允许自动解决时，工具会向管理员报告冲突。

“会尝试”和“可能会”保留。报告动作仍属于“检测到冲突且策略不允许自动解决”的分支。原文没有说明自动解决失败后的行为，改写也不补充。

## 错误信息：保留不确定性，不补排障建议

**原文**

> 处理请求的过程中可能发生了错误，原因可能是数据格式与服务端预期不匹配，而这种不匹配可能由客户端版本过旧引起。

**改后**

> 处理请求时可能发生了错误。原因可能是数据格式与服务端预期不匹配。这种不匹配可能由客户端版本过旧引起。

三个不确定判断都保留。原文没有要求检查或升级客户端，改写不添加这些操作。

## Agent 指令：条件覆盖整个动作

**原文**

> 只有当上游任务已经完成且没有报错时，下游 Agent 才应该继续读取输出制品，但是超时的时候有时会产生部分制品。

**改后**

> 只有上游任务已完成且未报错时，下游 Agent 才应该继续读取输出制品。超时时，有时会产生部分制品。

保留“只有…才”“应该”“继续”和“有时”。不能改成无条件的“然后读取制品”，也不能新增“丢弃部分制品”。

## README：压缩修饰，不编造实现

**原文**

> 本项目提供一个语义缓存模块，旨在降低 LLM 重复请求的成本，并支持通过配置文件对缓存有效期进行设置。

**改后**

> 本项目提供语义缓存模块，旨在降低 LLM 重复请求的成本。支持通过配置文件设置缓存有效期。

保留“旨在”所表达的目标。没有添加“已经降低成本”“不额外存储数据”或具体匹配算法，也没有推断哪个角色有配置权限。

## 含糊分支：保留缺口

**原文**

> 如果检测到冲突，可能按策略自动解决，否则交给管理员。

**处理**

> 如果检测到冲突，可能按策略自动解决，否则交给管理员。
>
> 保留原文：“否则交给管理员”；原因：“否则”可能指未检测到冲突、不允许自动解决或自动解决失败，需要明确条件。

未解决的歧义必须可见。更流畅的猜测不算成功的改写。

## 应保持原样的表达

| 原文 | 保留理由 |
|---|---|
| 已经完成部署。 | 保留完成状态，不能改成“部署”。 |
| 将缓冲区按 8 字节对齐。 | “对齐”是领域术语，数值和单位有意义。 |
| 校验签名后，审核申请。 | 两个动作不同，不做同义词合并。 |
| 文件已删除。 | 状态报告未必需要施事者。 |
| 请求字段名为 `request_id`。 | 中文描述和代码标识符可以并存。 |
| 仅管理员可以删除记录，审计记录除外。 | 保留权限、许可强度和例外。 |
| 在 2 秒内最多重试 3 次。 | 同时保留时间范围和次数上限。 |
| 失败时不要重试。 | 否定与触发条件都不能丢失。 |
