# 设计审查与实施记录

审查日期：2026-10-19。基线：`0e3ff2f`。范围：项目目标、skill 指令、示例、linter、README 和贡献者使用路径。

## 核心判断

项目最值得保留的目标是：在不改变含义的前提下，让中文技术文本更容易理解和执行。原版把“短句、主动语态、词表命中更少”与这一目标混在一起，导致规则、示例和检测器之间冲突。

目前能直接验证的是规则是否自洽、示例是否忠实、脚本是否按契约工作。要证明下游 Agent 更少误读，还需要模型对照和真实任务评估。不能从 lint 全绿推出这一结论。

## 产品与实现路线比较

| 方案 | 收益 | 代价或缺口 | 决定 |
|---|---|---|---|
| A. 仅整理 README 和例子 | 改动小，上手更快 | 规则矛盾与 linter 误报仍存在 | 作为本轮的一部分，单独做不够 |
| B. 语义保真 Skill + 保守 linter | 直接处理原意漂移，保留零依赖；检测器职责可解释 | 仍需模型或人工判断语义 | **本轮采用** |
| C. 以 linter 分数为主，扩展正则和黑话表 | 易做排行榜和 CI 门槛 | 容易奖励删情态、删条件、删术语；没有可靠质量标尺 | 不采用 |
| D. 引入中文分词、句法分析和语义判定服务 | 可能改善特定模式识别 | 增加依赖、模型成本和版本差异；仍需评估保真 | 有真实误报数据后再考虑 |

实现保持一个主要 Python 入口。`lint(text, filename, max_chars)` 返回提示和字符数，CLI 负责文件、选项与退出码。围栏、行内代码等预处理在一个位置完成，各条规则共用结果，避免多套扫描对同一段代码做出不同判断。没有引入配置框架或自动改写器。

## README 呈现路线比较

| 方案 | 适合情况 | 当前取舍 |
|---|---|---|
| 极简入口：一句话 + 安装 | 项目已有广泛认知，用户知道能力边界 | 不能解释本项目与普通润色的区别 |
| 示例与证据入口：效果示例 → 安装 → 使用 → 边界 → 评估 | 新使用者需要快速判断是否可信和适合 | **本轮采用** |
| 全量手册：规则、标准历史、实现细节集中在 README | 单文件分发、离线查阅 | 信息过多，安装和使用路径容易被淹没 |

README 保留用户决策所需内容。完整规则在 `SKILL.md`，设计理由、CLI 契约、示例、评估和贡献流程各有独立入口。移除 star 数、未经验证的效果背书以及尚未验证的发布渠道描述。

## 已实施的优化

1. **目标排序**：语义保真优先于句长与风格。
2. **指令收敛**：`SKILL.md` 从 14,041 缩至 6,165 UTF-8 字节，约减少 56%；这是文件体积，不是模型 token 测量。
3. **语义检查**：显式保护事实、情态、状态、否定、条件、范围、数字和执行顺序。
4. **歧义处理**：允许保留原文并说明缺口，避免猜主体或分支。
5. **示例修正**：去掉无依据的实现、数据和排障操作，补充应保持不变的表达。
6. **检查分级**：只让分号、句长和悬挂连词计入硬检查，其余提示需上下文复核。
7. **Markdown 处理**：共用屏蔽逻辑，修复不同长度围栏，支持匹配长度的行内代码及常见元数据和注释。
8. **CLI 契约**：新增字符预算，保持 JSON 字段与规则 ID，明确退出码与 baseline 的数量预算含义。
9. **对外文档**：修复安装路径，提供可复制的试用、导航、能力边界与贡献说明。
10. **验证分层**：脚本自检与独立回归进入 CI；模型效果使用独立案例与判据，不拿正则测试代替。

## 已验证结果

在本机 Python 3.11.2 上，内置 selftest 和 36 个独立回归测试通过；skill 格式校验通过。GitHub Actions 已配置 Python 3.10 / 3.12 / 3.14，尚未在远端运行，因此这些版本的结果不记为已通过。

以下结果是运行基线脚本与本轮脚本的直接对照。它们只验证已知缺陷，不是整体准确率：

| 输入 | 原版硬提示 / 建议 | 本轮硬提示 / 建议 |
|---|---|---|
| 将缓冲区按字节对齐。检查网络链路。 | 2 / 0 | 0 / 2 |
| 打开文件。启动服务。读取输出。获取令牌。 | 2 / 0 | 0 / 2 |
| 已经完成部署。 | 1 / 0 | 0 / 0 |

合法术语仍可能出现建议，收益是停止把不确定判断当成硬错误。若使用者依赖旧版把这些规则作为 CI 门槛，应参考 [迁移说明](../references/linter.md#从-01-行为迁移)。
