# 规则本地化决策说明

本文件是 ASD-STE100 → 中文的**逐条打磨记录**。对原规范的每条规则，我们回答三个问题：

1. **原规则在说什么？**（paraphrase，不复制原文）
2. **中文语境下这条还成立吗？**（判断依据）
3. **本 skill 怎么处理？**（保留 / 替换 / 新增 / 放弃）

这不是对原规范的翻译。英文的歧义来源（短语动词、现在完成时、分词歧义）和中文的歧义来源（"的"字堆叠、零主语、体标记混用、中英混排）只有部分重叠，机械翻译会得到一个在中文里既不严格又不好用的东西。

## ASD-STE100 原规范结构

- **53 条写作规则**，分 9 个章节：词汇、动词形式、语态、句子结构、名词短语、否定、标点、段落、文档结构。
- **~900 词已批准词典**，每个词限定一个义项、一种词性。
- **~1200 词待替换表**，给出推荐替换词。
- **术语许可**：组织可以在基础词典之外定义自己的"项目术语表"。

发行版本：Issue 9（2025 年 1 月），维护方 Simplified Technical English Maintenance Group (STEMG)。自 Issue 6（2013 年）起免费下载。

## 原规则逐条处理

### 词汇规则（原第 1 章 Word Choice）

| 原规则 paraphrase | 中文是否成立 | 本 skill 处理 |
|---|---|---|
| 只用已批准词、只用其已批准义项和词性 | 中文无一对一词典，不成立 | **放弃**词典依赖，**保留**底层原则："选最常用、最短、意义最窄的词；每次用同一个" |
| 一词一义（禁 context-based disambiguation） | 成立 | **保留**，加入扫查清单第 1 条（同义词轮换） |
| 偏好更朴素的常见词 | 成立 | **保留**，作为背景原则 |
| 动作用动词、不用动名化（Rule 3.7） | **强烈成立**。中文的"进行/做出/实施/开展/完成/发出 + 名词化"是最泛滥的赘述。 | **保留并强化**，列为结构规则一等公民 |
| 不要造短语动词（Rule 9.3，如 "take off"） | **不成立**：中文无短语动词 | **替换**：对应到中文的**虚化动词 + 名词化**。禁"进行分析 / 做出决定 / 发出通知"同一类赘述结构 |

### 动词形式（原第 4 章 Verb Forms）

| 原规则 paraphrase | 中文是否成立 | 本 skill 处理 |
|---|---|---|
| 只允许不定式、祈使、简单现在、简单过去、简单将来、分词作形容词 | **不成立**：中文无时态体系 | **替换**：对应到中文的**体标记（着/了/过/在/已/正在）一致**。同一动作在同一上下文里用同一组体标记，不混用 |
| 禁 present perfect（"have received" vs "received"） | **不成立**：中文无完成时 | **放弃**，由"体标记一致"吸收 |
| -ing 形式仅作技术名词 | **不成立**：中文无 -ing | **放弃** |

### 语态（原第 3 章 Voice）

| 原规则 paraphrase | 中文是否成立 | 本 skill 处理 |
|---|---|---|
| 操作指令必须主动语态 | **成立**，并且在中文里更棘手——"被字句"外还有"由 / 受 / 让 / 叫 / 为…所"多种被动，以及"受事主语句"（无被动标记但施事者缺失，如"文件已删除"） | **保留并扩展**：主动语态优先；特别打击"受事主语句"隐藏施事者 |
| 描述性文本允许被动，仅限施事者未知或无关 | 成立 | **保留** |

### 句子结构（原第 5-6 章）

| 原规则 paraphrase | 中文是否成立 | 本 skill 处理 |
|---|---|---|
| 一句一指令 | 成立 | **保留** |
| 指令句 ≤ 20 词、描述句 ≤ 25 词 | 单位需换算。1 英文词 ≈ 2 汉字（估） | **保留并换算**：指令 ≤ **40 汉字**、描述 ≤ **50 汉字**（含标点，不含空格） |
| 不要为省字而丢掉主语、谓语、冠词 | **强烈成立**，并且方向需要反着强调——中文可零主语，agent 场景不该省 | **保留并强调**：禁零主语和零宾语 |
| 名词连用 ≤ 3 层 | 成立 | **保留** |
| 禁分号（Rule 8.1） | 成立 | **保留** |

### 标点（原第 8 章）

| 原规则 paraphrase | 中文是否成立 | 本 skill 处理 |
|---|---|---|
| 禁分号（；） | **成立**，并且中文分号误用更泛 | **保留** |
| 允许其他标点 | 成立 | **保留** |

> 排版级规则（空格、全半角、数字格式）本 skill 不强推——这些在中文圈已有 `sparanoid/chinese-copywriting-guidelines` 等成熟方案，重复无益。但 skill 的"中英文术语二选一"规则会间接处理一部分中英混排问题。

### 段落与文档结构（原第 6-7 章）

| 原规则 paraphrase | 中文是否成立 | 本 skill 处理 |
|---|---|---|
| 一段一个主题 | 成立 | **保留** |
| 段 ≤ 6 句 | 成立 | **保留** |
| 流程 / 条件 / 枚举用列表 | 成立 | **保留** |

### 安全文本

| 原规则 paraphrase | 中文是否成立 | 本 skill 处理 |
|---|---|---|
| 安全指令必须以命令或条件开头，不能埋在中段 | 成立 | **保留**（在 SKILL.md 的"工作流程"里体现为"保留必要精度"原则） |

## 中文独有、原规范没有的规则（新增）

### N1. "的"字堆叠

**现象**：连续三个及以上"的"字短语堆到名词前。中文的定语都放在中心词前面，叠多了句子一头沉、读者需要在脑子里把结构倒置回来。

- Bad: "一个基于最新的 AI 技术的用于处理用户的请求的服务"
- Good: "一个处理用户请求的服务，基于最新 AI 技术"

**修法**：把定语后置成新句子，或改成名词的同位解释。

### N2. 零主语 / 零宾语歧义

**现象**：中文允许"主题句"和零主语，但 agent-facing 文本里省略会让下游无法恢复动作关系。

- Bad: "完成后请检查"（谁完成？检查什么？）
- Good: "任务完成后，用户检查输出文件"

**修法**：补全主语和宾语。这条和原规范的"禁省略"同向，但强度要调高。

### N3. 中英文术语二选一

**现象**：同一文档里"request / 请求"或"server / 服务器"混用，不仅破坏术语一致，还破坏术语检索。

- Bad: "将 request 发送到 server。后端处理这个请求后返回给客户端。"
- Good: 全部用中文（"将请求发送到服务器"）或全部用英文（"将 request 发送到 server"），一个文档只认一种

**修法**：挑一种，用到底。排版细节（中英文之间空格、全半角标点）交给 `sparanoid/chinese-copywriting-guidelines` 这类工具。

### N4. 互联网黑话 / 四字格 / 营销词

**现象**：中文技术文本里的"赋能、打通、拉通、落地、对齐、下沉、沉淀、复盘、抓手、心智、方法论、生态位、组合拳、底座、链路"等黑话，加上"丝滑、无缝、极致、全新、全方位、一站式、开箱即用"等营销形容词，让句子看起来说了很多实际什么都没说。四字格（"一气呵成、浑然一体、水到渠成"）在技术文档里也是信息密度低、意义模糊的来源。

- Bad: "通过底座能力赋能上层业务，一站式打通数据链路。"
- Good: "基础平台提供统一的 API，业务层直接调用。"

**修法**：删，或替换成具体可测量的说法。词表见 `scripts/ste-lint-zh.py` 里 `BUZZWORDS` 和 `MARKETING_ADJECTIVES`。

### N5. 情态词保留（强调一遍）

这条在原规范里只隐含在 "preserve meaning"，但对中文 agent-facing 文本尤其重要——"可能 / 也许 / 应该 / 或许 / 大概"是作者信心度的表达，删一个等于改断言。本 skill 的 linter **永不**对情态词报警，`--selftest` 把这个承诺写在断言里。

## 本 skill 不做的事

- **不复制 ASD 词典**。词典是英文的，中文无一一映射。
- **不做排版规则**（中英文之间空格、数字格式、全半角）。已有工具（见 CREDITS）更专业。
- **不做翻译**。本 skill 的输入和输出都是中文。
- **不做文体转换**（正式/口语/官腔）。文体是风格选择，不是歧义修复。
